# PP-Claw 个人微信接入指南

本文说明如何让 **皮皮虾 PP-Claw** 通过 **个人微信 ClawBot 协议** 接入微信，并最终实现：

- 微信用户给皮皮虾发消息
- 皮皮虾收到消息后进入 Agent 流程
- Agent 生成回复
- 回复再通过个人微信发回去

这是一份从零开始、可直接照着操作的文档。

---

## 1. 这套方案是什么

当前仓库里的个人微信接入，不是公众号，也不是企业微信回调，而是：

- 一个原生内置的 `wechat_personal` channel
- 通过 `gateway` 统一启动
- 使用 ClawBot 风格的 HTTP JSON API
- 通过扫码完成授权
- 登录凭证保存在本地
- 支持多个微信账号同时在线

对应代码入口：

- 渠道主实现：`channels/wechat_personal.go`
- API 协议封装：`channels/wechat_personal_api.go`
- 媒体收发与加密：`channels/wechat_personal_media.go`
- 状态持久化：`channels/wechat_personal_state.go`
- 登录 CLI：`cli/commands.go`
- 终端二维码渲染：`cli/wechat_qr.go`

---

## 2. 整体工作原理

可以把这条链路理解成 6 步：

1. `gateway` 启动时加载 `wechat_personal` 渠道
2. 你通过 CLI 执行 `pp-claw channels wechat login`
3. `gateway` 调微信后端获取二维码
4. 你用手机微信扫码授权
5. `gateway` 保存登录 token，并启动该微信账号的长轮询
6. 后续所有微信消息都通过 `MessageBus -> AgentLoop -> Outbound -> wechat_personal.Send()` 完成收发

简化消息流如下：

```text
微信 -> ClawBot API -> wechat_personal channel -> MessageBus -> AgentLoop
AgentLoop -> MessageBus -> wechat_personal channel -> ClawBot API -> 微信
```

## 3. 前提条件

开始前请确认以下条件成立：

### 3.1 代码版本

你使用的是已经包含 `wechat_personal` 的最新代码，并且已经重新编译：

```bash
go build -o pp-claw .
```

### 3.2 本地配置文件

默认配置文件路径：

```text
~/.pp-claw/pp-claw.yaml
```

### 3.3 gateway 端口不能被别的程序占用

这是最容易踩坑的一点。

如果你的本机 `18790` 已经被 Docker、旧 gateway 或其他服务占用，建议直接换端口，例如：

```yaml
gateway:
  host: 127.0.0.1
  port: 28790
```

如果不确定当前端口是不是空闲，可以执行：

```bash
lsof -n -P -iTCP:28790 -sTCP:LISTEN
```

## 4. 配置文件应该怎么写

最小可用配置如下。

如果你已经有 `~/.pp-claw/pp-claw.yaml`，只需要把下面的 `gateway` 和 `channels.wechat_personal` 合进去，不要重复写整个文件。

```yaml
agents:
  defaults:
    workspace: ~/.pp-claw/workspace
    model: your-model
    max_tokens: 8192
    temperature: 0.1
    max_tool_iterations: 40
    memory_window: 100

channels:
  send_progress: false
  send_tool_hints: false

  wechat_personal:
    enabled: true
    state_dir: ""
    base_url: "https://ilinkai.weixin.qq.com"
    cdn_base_url: "https://novac2c.cdn.weixin.qq.com/c2c"
    bot_type: "3"
    poll_timeout_ms: 35000
    login_timeout_s: 480
    session_pause_minutes: 60
    request_timeout_ms: 15000
    config_timeout_ms: 10000
    allow_from: []
    accounts:
      wx1:
        enabled: true
        base_url: ""
        cdn_base_url: ""
        bot_type: ""
        allow_from: []
        ilink_user_id: ""

gateway:
  host: 127.0.0.1
  port: 28790
  heartbeat:
    enabled: true
    interval_s: 1800
```

### 4.1 每个字段是什么意思

#### `channels.wechat_personal.enabled`

必须是 `true`。

如果这里是 `false`：

- `gateway` 不会初始化微信渠道
- `/channels/wechat_personal/login/start` 路由不会注册
- 执行登录命令时会出现 `404`

#### `base_url`

微信 ClawBot 后端 API 基地址。

默认：

```yaml
base_url: "https://ilinkai.weixin.qq.com"
```

#### `cdn_base_url`

微信媒体上传下载 CDN 地址。

默认：

```yaml
cdn_base_url: "https://novac2c.cdn.weixin.qq.com/c2c"
```

#### `bot_type`

二维码登录所使用的 bot 类型。

默认：

```yaml
bot_type: "3"
```

#### `accounts`

这里定义本地管理的微信账号实例。

例如：

```yaml
accounts:
  wx1:
    enabled: true
  wx2:
    enabled: true
```

表示后续允许登录两个不同的微信账号，分别对应 `wx1` 和 `wx2`。

#### `allow_from`

微信用户白名单。

如果为空：

- 不限制来源

如果填写了值：

- 只有这些微信用户 ID 才允许与 Agent 对话

## 5. 第一次启动前要做什么

### 5.1 重新编译

如果你刚拉代码或者刚修改过配置，先重新编译：

```bash
go build -o pp-claw .
```

### 5.2 检查配置是否生效

执行：

```bash
./pp-claw channels status
```

正常应该能看到：

```text
wechat_personal enabled
accounts=1
```

如果这里还是 `disabled`，说明你改错了配置文件，或者用了错误的 `-c` 参数。

---

## 6. 如何启动 gateway

所有 channel 都必须由 `gateway` 启动，个人微信也不例外。

执行：

```bash
./pp-claw gateway
```

建议把这个终端保持打开。

### 6.1 验证 gateway 是否真的启动成功

新开一个终端，执行：

```bash
curl --noproxy '*' http://127.0.0.1:28790/health
```

如果返回：

```text
ok
```

说明当前端口上运行的就是你的本地 gateway。

再执行：

```bash
curl --noproxy '*' http://127.0.0.1:28790/channels/status
```

返回的 JSON 里应该有：

- `wechat_personal`

如果没有，说明：

- 运行中的 gateway 不是最新版本
- 或 `wechat_personal.enabled` 没开
- 或启动时用了别的配置文件

---

## 7. 如何发起微信扫码登录

另开一个终端，执行：

```bash
./pp-claw channels wechat login --account wx1
```

这里的 `wx1` 对应你配置文件里的：

```yaml
channels:
  wechat_personal:
    accounts:
      wx1:
```

### 7.1 登录时会发生什么

CLI 会做两件事：

1. 请求 `gateway`：

```text
POST /channels/wechat_personal/login/start
```

2. 再轮询等待扫码结果：

```text
POST /channels/wechat_personal/login/wait
```

### 7.2 终端里会看到什么

正常会看到：

- 账号 ID
- 二维码链接
- 终端二维码
- 登录成功提示
- `微信用户 ID`

例如：

```text
账号 ID: wx1
二维码链接: https://liteapp.weixin.qq.com/q/...
提示: 请使用微信扫描二维码并在手机上确认授权。
...
登录成功
账号 ID: wx1
微信用户 ID: o9cq801BWdfKPJjKT3eBrNgqdr_k@im.wechat
后端地址: https://ilinkai.weixin.qq.com
```

### 7.3 为什么终端二维码现在能显示

微信返回的 `qrcode_url` 不一定是 PNG/JPG 图片。

有些情况下它是这种链接：

```text
https://liteapp.weixin.qq.com/q/...
```

这个链接本身是一个前端页面，不是图片。

当前实现已经兼容了两种情况：

1. 如果返回的是图片地址，就直接下载图片并渲染
2. 如果返回的是登录链接，就直接把这个链接本身编码为终端二维码

所以现在即使 `qrcode_url` 不是图片，也可以扫码。

## 8. 登录成功后，凭证存在哪里

默认状态目录：

```text
~/.pp-claw/workspace/channels/wechat_personal/
```

其中主要会包含：

```text
accounts/
media/
```

账号状态文件大致会保存：

- `account_id`
- `token`
- `ilink_user_id`
- `base_url`
- `cdn_base_url`
- `get_updates_buf`
- `typing_ticket`
- `paused_until`

也就是说：

- 你第一次扫码登录成功后
- 以后只要 token 没过期
- 重新启动 `gateway` 就会自动恢复这个微信账号

## 9. 登录后如何确认账号真的在线

执行：

```bash
./pp-claw channels wechat status
```

正常会看到类似：

```text
wechat_personal 状态:
  - wx1  running  logged-in
    user_id: o9cq801BWdfKPJjKT3eBrNgqdr_k@im.wechat
    base_url: https://ilinkai.weixin.qq.com
```

这说明：

- `wx1` 账号已经登录
- 长轮询已经在运行
- 后续微信消息可以进入 Agent

## 11. 为什么 `context_token` 很重要

个人微信这套协议里，回复消息不是只靠：

- `chat_id`
- `reply_to`

而是必须依赖：

- `context_token`

接收消息时，微信后端会在每条入站消息里带上：

```text
context_token
```

皮皮虾会把它缓存下来，键是：

```text
account_id + ":" + user_id
```

发送消息时再把这个 token 原样带回去。

如果没有这个 token，就会出现：

- 无法发送
- 或发送后上下文不对

所以这条链路里，`context_token` 是必须品，不是可选项。

## 12. 微信消息是怎么进入 Agent 的

### 12.1 收消息

每个已登录账号都会启动自己的 monitor loop。

逻辑是：

1. 读取本地保存的 `get_updates_buf`
2. 调用：

```text
POST ilink/bot/getupdates
```

3. 拿到新的消息列表和新的 `get_updates_buf`
4. 更新本地 cursor
5. 把微信消息转换成统一 `InboundMessage`
6. 发布到 `MessageBus`

### 12.2 进入 AgentLoop

进入 `MessageBus` 后，就和其他渠道一样：

- `AgentLoop` 消费消息
- 拼装上下文
- 走模型推理
- 需要时调用工具
- 生成最终 `OutboundMessage`

### 12.3 回发微信

出站时：

1. `ChannelManager` 根据 `channel=wechat_personal` 路由到微信渠道
2. 微信渠道根据 `AccountID` 找到目标账号
3. 用 `ChatID` 找到目标微信用户
4. 从缓存读取 `context_token`
5. 调用：

```text
POST ilink/bot/sendmessage
```

---

## 13. 媒体消息为什么需要 CDN + AES

微信媒体不是简单的文件 URL。

出站时流程如下：

1. 读取本地文件
2. 计算明文 MD5 和大小
3. 生成 AES key
4. 调用：

```text
POST ilink/bot/getuploadurl
```

5. 拿到上传参数
6. 用 AES-128-ECB 加密文件
7. 上传到微信 CDN
8. 获取 `x-encrypted-param`
9. 构造 `CDNMedia`
10. 再通过 `sendmessage` 把媒体消息发出去

入站时则反过来：

1. 解析媒体引用
2. 从 CDN 拉取密文
3. 根据 `aes_key` 解密
4. 保存到本地临时文件
5. 再把本地文件路径作为 `InboundMessage.Media`

所以：

- Agent 核心并不直接理解微信媒体协议
- 这些细节都封装在 `wechat_personal_media.go` 里

## 14. 常见排障

### 14.1 登录命令报 404

如果看到：

```text
gateway POST /channels/wechat_personal/login/start 返回 404
```

说明运行中的 `gateway` 没有注册微信路由。

优先检查：

1. `channels.wechat_personal.enabled` 是否是 `true`
2. 当前 `gateway` 是否真的是你刚编译的版本
3. 端口上跑的是不是别的服务
4. 修改配置后是否重启了 `gateway`

### 14.2 配置里已经 enabled，但仍然 404

这通常说明你请求打到了**错误的服务**。

典型场景：

- `18790` 被 Docker 占用
- 你本地 `gateway` 其实没起来
- 或配置里的 `port` 和实际监听端口不一致

建议执行：

```bash
curl --noproxy '*' http://127.0.0.1:28790/health
lsof -n -P -iTCP:28790 -sTCP:LISTEN
```

### 14.3 登录时二维码渲染失败

当前版本已经兼容：

- 图片型二维码
- 链接型二维码

如果仍失败，CLI 至少会打印出 `二维码链接`，这时直接复制到浏览器打开即可。

### 14.4 登录成功，但收不到消息

优先检查：

1. `./pp-claw channels wechat status` 是否显示 `running`
2. 是否使用了正确的账号
3. `allow_from` 是否误限制了发信人
4. token 是否过期被暂停

### 14.5 会话过期

如果微信后端返回：

```text
errcode = -14
```

系统会将该账号标记为暂停一段时间，避免疯狂重试。

这时通常需要重新扫码登录。

## 15. 多账号如何用

如果你要接多个个人微信号，可以这样写：

```yaml
channels:
  wechat_personal:
    enabled: true
    accounts:
      wx1:
        enabled: true
      wx2:
        enabled: true
      wx3:
        enabled: true
```

然后分别登录：

```bash
./pp-claw channels wechat login --account wx1
./pp-claw channels wechat login --account wx2
./pp-claw channels wechat login --account wx3
```

每个账号都会：

- 单独保存 token
- 单独维护 `get_updates_buf`
- 单独维护 `context_token`
- 单独进入自己的长轮询

对应上下文隔离维度是：

```text
channel + account_id + chat_id
```

所以不同微信号之间不会串会话。

## 16. 推荐上线前检查清单

在正式使用前，建议按这份清单逐项确认：

- `~/.pp-claw/pp-claw.yaml` 中 `wechat_personal.enabled = true`
- `gateway.host` 使用 `127.0.0.1`
- `gateway.port` 没被其他程序占用
- `./pp-claw channels status` 中显示 `wechat_personal enabled`
- `./pp-claw gateway` 已启动
- `/health` 返回 `ok`
- `/channels/status` 能看到 `wechat_personal`
- `./pp-claw channels wechat login --account wx1` 登录成功
- `./pp-claw channels wechat status` 显示 `running` 和 `logged-in`
- 用微信发送一条文本消息，皮皮虾能正常回复

## 17. 当前实现边界

当前实现已经可以用于个人微信文本和基础媒体对话，但仍有边界需要知道：

- 这是个人微信协议接入，不是公众号官方 webhook
- 长期稳定性依赖微信后端协议本身
- 终端二维码虽然已兼容链接型二维码，但不同终端字体/缩放下扫码体验可能不同
- 真实环境下媒体格式、视频缩略图、特殊文件类型可能还需要继续打磨

所以它现在的定位是：

- **可用**
- **可继续扩展**
- **已具备正式联调基础**
